SCENARIO 2: First Student Applies
┌─────────────────────────────────────────────────────────────────────────────┐

│ → Status changed from ACTIVE to PENDING                                     │

↓ STUDENT 2 APPLIES

SCENARIO 3: Second Student Applies (FIFO Queue)
┌─────────────────────────────────────────────────────────────────────────────┐

│ Queue Position 1: Ali Ahmed - FA21-BSE-001                                  │
│ Queue Position 2: Usman Tariq - FA21-BSE-015                                │
│ → Second student joins queue                                                │
│ → Status remains PENDING                                                    │
│ → total_queue_member = 2                                                    │
│ → Queue display: 1/5 (total_queue_member - 1 = 2 - 1 = 1)                  │
└─────────────────────────────────────────────────────────────────────────────┘

↓ STUDENT 3 APPLIES

SCENARIO 4: Third Student Applies
┌─────────────────────────────────────────────────────────────────────────────┐
│ Time: 9:00-10:00 │ Status: PENDING (YELLOW) │ Queue: 2/5                   │
│ Queue Position 1: Ali Ahmed - FA21-BSE-001                                  │
│ Queue Position 2: Usman Tariq - FA21-BSE-015                                │
│ Queue Position 3: Hassan Khan - FA21-BSE-022                                │
│ → Third student joins queue                                                 │
│ → total_queue_member = 3                                                    │
│ → Queue display: 2/5 (total_queue_member - 1 = 3 - 1 = 2)                  │
└─────────────────────────────────────────────────────────────────────────────┘

↓ MORE STUDENTS APPLY

SCENARIO 5: Queue Full
┌─────────────────────────────────────────────────────────────────────────────┐
│ Time: 9:00-10:00 │ Status: PENDING (YELLOW) │ Queue: 4/5 (FULL)            │
│ Queue Position 1: Ali Ahmed - FA21-BSE-001                                  │
│ Queue Position 2: Usman Tariq - FA21-BSE-015                                │
│ Queue Position 3: Hassan Khan - FA21-BSE-022                                │

│ → Queue is now FULL (Maximum 5 allowed)                                     │
│ → total_queue_member = 5                                                    │

│ → No more students can apply to this slot                                   │
└─────────────────────────────────────────────────────────────────────────────┘

↓ ADMIN APPROVES REQUEST #1

SCENARIO 6: Admin Approves First Student
┌─────────────────────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────────────────────┘

↓ ADMIN REJECTS ALL REQUESTS

SCENARIO 7: Admin Rejects All Requests
┌─────────────────────────────────────────────────────────────────────────────┐
│ Time: 9:00-10:00 │ Status: ACTIVE (GREEN) │ Queue: 0/5                     │
│ → Admin rejected all pending requests                                       │
│ → Status returns to ACTIVE                                                  │
│ → Slot is available again for new bookings                                  │
│ → Queue is cleared                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

---------------------------- QUEUE CALCULATION FORMULA -------------------------

Formula: Queue Display = (total_queue_member - 1) / 5

Examples:
- 1 student applies  → total_queue_member = 1 → Display: 0/5
- 2 students apply   → total_queue_member = 2 → Display: 1/5
- 3 students apply   → total_queue_member = 3 → Display: 2/5
- 4 students apply   → total_queue_member = 4 → Display: 3/5
- 5 students apply   → total_queue_member = 5 → Display: 4/5 (FULL)

-------------------------------- SYSTEM RULES ----------------------------------

WEEKEND SKIP LOGIC - WORKING DAYS ONLY
Rule: "Next 2 days" means next 2 WORKING days (Monday-Friday only)

Algorithm:
1. Start from current date
2. Count forward, skipping Saturday and Sunday
3. Mark next 2 working days as clickable
4. Saturday and Sunday are ALWAYS RED and non-clickable
5. All other dates are locked

Examples:
- Thursday  → Clickable: Thu, Mon, Tue (skip Sat/Sun)
- Friday    → Clickable: Fri, Mon, Tue (skip Sat/Sun)
- Monday    → Clickable: Mon, Tue, Wed
- Tuesday   → Clickable: Tue, Wed, Thu
- Wednesday → Clickable: Wed, Thu, Fri

-------------------------------- SYSTEM RULES ----------------------------------

SLOT READ-ONLY RULE (CRITICAL)
When admin APPROVES a booking request:
- Status changes from PENDING → APPROVED
- Slot becomes READ-ONLY for ALL users
- User cannot click on the slot anymore
- UI shows: "FULL" with blue background
- No booking form will appear for this slot
- This is FINAL state until booking time expires

Example:
┌─────────────────┬─────────────────┬─────────────────┬─────────────────┐
│   9:00-10:00    │  10:00-11:00    │  11:00-12:00    │  12:00-1:00     │
│                 │                 │                 │                 │
│   STATUS:       │   STATUS:       │   STATUS:       │   STATUS:       │
│   ACTIVE        │   PENDING       │   APPROVE       │   ACTIVE        │
│   (GREEN BG)    │   (YELLOW BG)   │   (BLUE BG)     │   (GREEN BG)    │
│                 │                 │                 │                 │
│   [AVAILABLE]   │   Queue: 2/5    │   FULL          │   [AVAILABLE]   │
│   (Clickable)   │   (Clickable)   │   READ-ONLY     │   (Clickable)   │
│                 │                 │   (Not Clickable)                 │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┘

Frontend Logic:
IF slot.status == "APPROVED":
    - Disable click event
    - Show blue background
    - Display "FULL" text
    - No pop-up form on click
ELSE IF slot.status == "PENDING":
    - Show yellow background
    - Display queue position
    - Allow click (show queue info)
ELSE IF slot.status == "ACTIVE":
    - Show green background
    - Display "AVAILABLE"
    - Allow click (open booking form)

---------------------------- API ENDPOINTS STRUCTURE ---------------------------

ROOM MANAGEMENT:
- GET /api/rooms              - List all rooms
- GET /api/rooms/{id}         - Get room details
- POST /api/rooms             - Create new room
- PUT /api/rooms/{id}         - Update room
- DELETE /api/rooms/{id}      - Delete room

BOOKING MANAGEMENT:
- GET /api/bookings           - List all bookings
- GET /api/bookings/date/{date} - Get bookings by date
- GET /api/bookings/room/{roomId}/date/{date} - Get room bookings for date
- POST /api/bookings          - Create booking request
- PUT /api/bookings/{id}      - Update booking
- PUT /api/bookings/{id}/approve - Approve booking (Admin)
- PUT /api/bookings/{id}/reject  - Reject booking (Admin)
- DELETE /api/bookings/{id}   - Cancel/delete booking

QUEUE MANAGEMENT:
- GET /api/queue/{roomId}/{date}/{timeSlot} - Get queue status
- POST /api/queue/join        - Join queue
- POST /api/queue/leave       - Leave queue

STUDENT/MEMBER MANAGEMENT:
- GET /api/students           - List all students
- GET /api/students/{id}      - Get student details
- POST /api/students          - Register student
- PUT /api/students/{id}      - Update student
- GET /api/members/student/{studentId} - Get members by student

AUTHENTICATION:
- POST /api/auth/login        - User login
- POST /api/auth/register     - User registration
- POST /api/auth/admin/login  - Admin login
