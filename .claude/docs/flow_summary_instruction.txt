# Comprehensive Prompt for Future Self - Adaptive Task Analysis & Prompt Generation

## Purpose
This prompt enables efficient task-specific analysis and prompt generation for various development scenarios.

---

## Task Classification & Approach

### Simple Tasks (Single Task Type, ≤3 sections)
When user requests one specific analysis type, create a focused prompt using that task's methodology.

### Complex Tasks (Multiple Task Types, >3 sections)
When user needs comprehensive analysis across multiple dimensions, create an adaptive prompt with multiple task sections.

---

## Task Type Reference

### TASK 1: Code Quality Assessment
**When**: Code review, quality audits, technical debt assessment
**Output**: Quality metrics, issue categorization, security review

#### Process Flow (Graph Form)
```
Code Review → Metric Collection → Issue Categorization → Security Review → Quality Score
     ↓              ↓                    ↓                 ↓             ↓
  Analyze     Quantify          Classify Severity    Security Check    Report
```

#### Process Flow (Details)
1. **Initial Analysis**: Review code structure, identify patterns, count LOC
2. **Metric Collection**: Calculate complexity, identify technical debt, measure changes
3. **Issue Identification**: Find bugs, security issues, performance problems
4. **Severity Classification**: Categorize as Critical/Important/Minor
5. **Security Review**: Check for vulnerabilities, validate patterns
6. **Quality Scoring**: Assign numerical score with improvement suggestions

#### Success Factors
- Complete metric coverage (lines, complexity, technical debt)
- Accurate severity classification
- Actionable recommendations
- Security vulnerability identification
- Performance impact assessment

#### Before/After Behavior with Scenarios
**Scenario: Memory Leak Detection**
- **BEFORE**: `document.body.appendChild(link)` - object URLs never released
- **AFTER**: Added `URL.revokeObjectURL(url)` after link removal
- **IMPACT**: Memory usage reduced from 500MB to 50MB, prevented browser crashes

### TASK 2: UI/UX Design Problem Analysis
**When**: UI/UX issues, user interaction problems, interface optimization
**Output**: Navigation breakdown, performance impact, user experience assessment

#### Process Flow (Graph Form)
```
User Action → Component Load → Data Fetch → State Update → Render
     ↓            ↓              ↓            ↓           ↓
  Click/Tap    Mount Effect     API Call     Set State   UI Update
```

#### Process Flow (Details)
1. **Action Identification**: Map user actions (click, scroll, navigation)
2. **Component Analysis**: Review component lifecycle, state management
3. **Data Flow Tracking**: Trace API calls, data transformation, state updates
4. **Performance Measurement**: Count API calls, measure load times, assess data transfer
5. **UX Impact Assessment**: Evaluate user friction, identify broken flows
6. **Optimization Recommendations**: Suggest caching, lazy loading, state optimization

#### Success Factors
- Complete navigation flow mapping
- Accurate performance metrics (API calls, load times, data size)
- Clear UX pain point identification
- Actionable optimization suggestions
- User impact quantification

#### Before/After Behavior with Scenarios
**Scenario: Day-to-Day Navigation Data Loss**
- **BEFORE**: DayView clears all state on day change → 10-16 API calls per cycle → 1.7-3.4s load time
- **AFTER**: Preserve day data in sessionStorage → 2-3 API calls per cycle → 0.3-0.5s load time
- **IMPACT**: 85% performance improvement, zero data loss, seamless navigation

### TASK 3: Data Flow Problem Analysis & Planning
**When**: Data flow problems, pipeline planning, consistency issues
**Output**: Data loss scenarios, flow analysis, integrity assessment

#### Process Flow (Graph Form)
```
Data Source → Transform → Validation → Storage → Retrieval → Display
     ↓           ↓          ↓          ↓         ↓         ↓
   Input     Process     Check      Database   Query    UI Render
```

#### Process Flow (Details)
1. **Source Analysis**: Identify data origins (API, database, user input)
2. **Transformation Tracking**: Map data processing steps, validation rules
3. **Storage Pattern Review**: Analyze database operations, transactions, constraints
4. **Retrieval Optimization**: Review query patterns, indexing, caching
5. **Consistency Validation**: Check for race conditions, stale data, sync issues
6. **Integrity Assessment**: Verify data accuracy, completeness, durability

#### Success Factors
- Complete data flow visualization
- Identification of all data loss points
- Clear consistency guarantees
- Actionable integrity improvements
- Performance optimization opportunities

#### Before/After Behavior with Scenarios
**Scenario: Profile Completion Data Loss**
- **BEFORE**: User completes profile → stored in database → DayView clears UI state → data appears lost
- **AFTER**: Complete profile → database + sessionStorage → DayView preserves state → data persists
- **IMPACT**: 100% data persistence, user confidence restored, zero work loss

### TASK 4: Deep Code Analysis on Specific Problems
**When**: Targeted debugging, problem isolation, issue investigation
**Output**: Root cause analysis, impact assessment, solution options

#### Process Flow (Graph Form)
```
Symptom → Investigation → Root Cause → Impact Analysis → Solution Design
   ↓           ↓              ↓             ↓               ↓
  Error    Trace Code    Find Source   Assess Damage   Implement Fix
```

#### Process Flow (Details)
1. **Symptom Documentation**: Record error messages, reproduction steps, affected areas
2. **Code Tracing**: Follow execution path, identify failing functions, locate error points
3. **Root Cause Identification**: Pinpoint exact line/condition causing issue
4. **Impact Assessment**: Determine scope, affected users, data corruption risk
5. **Solution Design**: Develop fix, test scenarios, migration strategy
6. **Verification Plan**: Create test cases, validation steps, rollback procedures

#### Success Factors
- Precise root cause identification
- Accurate impact assessment
- Clear solution approach
- Comprehensive testing strategy
- Minimal risk implementation

#### Before/After Behavior with Scenarios
**Scenario: Optional Chaining Bug**
- **BEFORE**: `weekPlan.id` crashes when weekPlan undefined → API fails → counts reset to 0
- **AFTER**: `weekPlan?.id` safely handles undefined → API succeeds → counts persist correctly
- **IMPACT**: Eliminated crashes, fixed data loss, improved user experience

### TASK 5: Flow Chart/Diagram Creation
**When**: Complex logic flows, process documentation, workflow visualization
**Output**: Step-by-step flow diagram, success/failure points

#### Process Flow (Graph Form)
```
Start → Decision Point → Process Step → Decision → End
 ↓          ↓              ↓           ↓        ↓
Init    Check Condition  Execute    Validate   Complete
```

#### Process Flow (Details)
1. **Process Identification**: List all steps, decisions, branches
2. **Flow Mapping**: Create sequential steps, identify parallel paths
3. **Decision Point Analysis**: Mark all conditional logic, error handling
4. **Success Path Definition**: Trace happy path, success conditions
5. **Failure Path Mapping**: Identify error scenarios, exception handling
6. **Visual Representation**: Create clear diagrams with labels, arrows, symbols

#### Success Factors
- Complete process coverage
- Clear decision points
- Accurate success/failure paths
- Easy-to-understand visualization
- Actionable insights

#### Before/After Behavior with Scenarios
**Scenario: Profile Completion Flow**
- **BEFORE**: User clicks complete → API call → database update → UI reload (complex, unclear)
- **AFTER**: Step 1: User clicks complete → Step 2: API validates → Step 3: DB updates → Step 4: UI animates → Complete
- **IMPACT**: Clear 4-step process, easy debugging, simplified maintenance

## Implementation Pattern

### Step 1: Task Identification
1. Read user's problem description
2. Identify relevant task type(s)
3. Count sections needed (≤3 = Simple, >3 = Complex)

### Step 2: Template Assembly
For each selected task type:
1. Extract methodology pattern
2. Fill placeholders with user's specific data
3. Add hallucination prevention constraints
4. Include verification checklist

### Step 3: Adaptive Prompt Generation
Combine selected templates into structured prompt:

```
# TASK ANALYSIS: [Problem Summary]

## CONTEXT
[User's problem description]
[Relevant files/systems involved]

## SELECTED TASK TYPES
Using [Task 1], [Task 2], etc. based on requirements

## ANALYSIS FRAMEWORK

### [TASK 1 NAME]
**Process Flow (Graph)**:
[Short flow diagram]

**Process Flow (Details)**:
[Detailed step-by-step]

**Success Factors**:
[List key factors]

**Before/After with Scenarios**:
- **BEFORE**: [Current state]
- **AFTER**: [Desired state]
- **IMPACT**: [Measurable outcome]

[Template content with placeholders filled]
[Constraints specific to this task]
[Verification checklist]

## UNIVERSAL CONSTRAINTS
⚠️ DO NOT MODIFY:
- Any existing code outside explicit scope
- Unrelated features or functionality
- Database structure unless specified
- API contracts or interfaces

✅ MUST PRESERVE:
- Existing patterns and conventions
- Current functionality
- Code style and formatting

## OUTPUT REQUIREMENTS
[Specific deliverables based on task types]

## SUCCESS CRITERIA
[Measurable outcomes]
```

## Placeholder Reference

Use these placeholders throughout templates:

- `[PROBLEM]` - User's problem description
- `[SYSTEM]` - System/application name
- `[FILES]` - Relevant files/paths
- `[SCENARIOS]` - Specific scenarios to analyze
- `[METRICS]` - Current metrics if available
- `[NAVIGATION_TYPES]` - User action types (navigation, tab switch, etc.)
- `[DATA_TYPES]` - Types of data affected
- `[ROOT_CAUSES]` - Identified or suspected causes
- `[FLOWS]` - Processes to diagram
- `[LOGIC_POINTS]` - Key logic concepts to analyze
- `[SOLUTIONS]` - Options to compare
- `[CHANGES]` - Code changes to analyze

## Hallucination Prevention Constraints

**Include in EVERY task type**:

1. **DO NOT assume** implementation details not provided by user
2. **DO NOT modify** any code outside the explicit scope mentioned
3. **ONLY analyze** the specific problem described, not related issues
4. **VERIFY** each template section applies to the actual task
5. **BASE all analysis** on user's provided context and file contents

**Additional Constraints by Task Type**:

- **TASK 1**: Only quantify metrics visible in code or specified by user
- **TASK 2**: Only analyze navigation types explicitly mentioned
- **TASK 3**: Only document data flows actually described
- **TASK 4**: Only identify root causes with evidence
- **TASK 5**: Only diagram flows that are clearly defined
- **TASK 6**: Only create logic for requirements specified
- **TASK 7**: Only generate scenarios based on given context
- **TASK 8**: Only compare aspects explicitly mentioned
