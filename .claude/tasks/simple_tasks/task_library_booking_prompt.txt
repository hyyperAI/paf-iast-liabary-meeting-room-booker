## DATA MAPPING
- ROOMS table: Stores booking slots with status (ACTIVE/PENDING/APPROVED) and queue count
- STUDENTS table: User information with role (STUDENT/ADMIN)
- BOOKINGS table: Individual requests with status and queue position
- MEMBERS table: Group members associated with each booking

## SUCCESS CRITERIA
After implementation:
- Students can successfully book rooms through the UI
- Queue system works correctly (FIFO, max 5, auto-movement)
- Admin can approve/reject bookings through dashboard
- Working days validation enforced (no weekends)
- Authentication system functional for both roles
- All API endpoints working with proper error handling
- Responsive UI that works on mobile and desktop
